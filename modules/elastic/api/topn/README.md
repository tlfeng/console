# Agentless Advanced TopN

Supported Advanced Agentless charts try the new ranking by default on the system monitoring store. The ordinary Console metrics write alias (for example, `.infini_metrics`, with the configured ORM prefix) is used for the query, not the legacy search wildcard that can also match summary indices. Manual selections are unchanged.

Node charts try one bounded search first. Index charts prefer PIT (two searches for peaks or pagination for counters) when strict PIT is available: Easysearch, Elasticsearch 8.16+, and OpenSearch 2.4+. Older or unsupported versions try one bounded search without PIT. A sentinel detects truncated candidate sets; a partial result is never ranked. Node charts can try PIT after an unsuccessful bounded scan; index charts can try the bounded search when PIT cannot be opened. These attempts share the same deadline. If neither can produce a complete result, supported automatic charts explain the failure instead of showing the legacy activity ranking.

By default, the same search or snapshot is checked for an authorized raw sample at or before the start of the displayed window. The optional counter pre-read bucket does not move this check earlier; if that bucket has no comparable samples, the first difference is omitted. This guard is not proof that the window has no collection or retention gaps.

Nonstandard deployments can optionally override the target and supply a known raw event-time coverage boundary:

```yaml
insight:
  topn:
    raw_index: .infini_metrics
    raw_from: "2026-01-01T00:00:00Z" # example: use the actual guaranteed coverage boundary
```

`raw_index` must be a trusted raw index or alias, not a wildcard. `raw_from`, if set, replaces the automatic check with an operator assertion. Update it before originals expire. Do not infer it solely from retention policy or the rollup routing threshold. Only explicit `cluster_id` matches are accepted; UUID-only samples are not included in the new ranking.

The first batch covers 17 index and 27 node single-field peaks. The second covers 20 index and 43 node derived metrics: rates, operation latencies, same-bucket ratios and positive store-size change. The node count describes backend keys; the Advanced page exposes a version-dependent subset. Document percentage (`doc_percent`) is not a TopN chart and stays on the existing path.

All paths score and draw from the same validated points. Zero is valid when measured; a missing field or a latency without requests is not a zero. Ratios require both fields from the same bucket and a positive denominator (total bytes for disk). The previous complete bucket may be read to evaluate the first visible difference; its samples do not rank. Missing or non-adjacent buckets, index UUID/node ID changes, detectable topology changes and counter resets are not scored. For node differences, the Agentless Framework collector stores the estimated JVM start (`jvm.timestamp - jvm.uptime_in_millis`) as `payload.elasticsearch.node_stats.jvm.start_time_estimate_in_millis`. It is an integer millisecond value; raw metrics mappings must allow numeric doc values (the default mappings infer a `long`). In the same search or PIT, if every observation in the query scope has the field, only the minimum, maximum and value count per bucket are returned. The value count must match the bucket's sample count. In mixed windows, the query still uses summaries for new samples; only samples without an estimate require the bounded per-sample lookup (up to 64 such observations per bucket). Missing, truncated or mixed-lifetime buckets break both neighboring differences; estimated starts must agree within one second. No historical backfill is performed. Long-window improvements require that the new collector has populated the entire scan, including any optional preceding bucket used in a difference. Direct gauges and ratios are unchanged. Storage decreases are skipped but remain the baseline for the next bucket. GC time keeps its legacy per-second formula and units. This is a ranking of retained valid monitoring samples, not proof that collection or counter continuity was perfect.

The initial limits are deliberately conservative: 512 visible time buckets, four concurrent exact requests per Console process, up to 32 storage shards per PIT, a five-second query deadline, and 16 MiB of cumulative search response data. Composite scans also stop at 24 search pages (including a possible terminal probe) or 150,000 entity-time buckets. The page size is reduced for wider windows. These are protections, not production performance guarantees. Budget rejection discards any partial ranking and suggests a shorter window, a larger interval, or manual selection. A complete empty result still renders as an empty chart. Agent, manual selection, and `doc_percent` retain their existing paths.

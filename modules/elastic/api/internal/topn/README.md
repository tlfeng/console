# Agentless Advanced TopN

Supported Advanced Agentless charts try the new ranking by default on the system monitoring store. The ordinary Console metrics write alias (for example, `.infini_metrics`, with the configured ORM prefix) is used for the query, not the legacy search wildcard that can also match summary indices. Advanced Agentless manual selection uses the same raw bucket and point rules for supported index and node charts. It queries authorized exact index names or explicit node transport addresses, and displays available curves in request order without ranking or reading summary scores. Legacy node selectors without `node_selector=transport_address`, other pages, and `doc_percent` are unchanged. Node counter searches try one bounded search and may fall back to PIT within the same deadline.

Node and index charts prefer one strict PIT snapshot when the store supports it (Easysearch, Elasticsearch 8.16+, and OpenSearch 2.4+): two searches for peaks or pagination for counters. If the snapshot cannot open, the same request falls back to one bounded single search. Older or unsupported versions always use the bounded single search. The bounded search carries a sentinel that proves the candidate set is too large to rank completely; a partial result is never ranked. These attempts share the same deadline. If neither can produce a complete result, supported automatic charts explain the failure instead of showing the legacy activity ranking.

TopN ranks the available valid monitoring samples within the requested bounds. Missing observations are not zero; a missing predecessor omits the difference, and gaps can break lines. No usable points after a complete search produces an empty chart. Failed, partial or truncated searches never produce an empty or partial ranking.

The optional `insight.topn.raw_index` overrides the trusted original index or alias (not a wildcard or rollup). Only explicit `cluster_id` matches are accepted; UUID-only samples are not included.

The first batch covers 17 index and 27 node single-field peaks. The second covers 20 index and 43 node derived metrics: rates, operation latencies, same-bucket ratios and positive store-size change. The node count describes backend keys; the Advanced page exposes a version-dependent subset. Document percentage (`doc_percent`) is not a TopN chart and stays on the existing path.

All paths score and draw from the same validated points. Zero is valid when measured; a missing field or a latency without requests is not a zero. Ratios require both fields from the same observation and a positive denominator (total bytes for disk). A parameterized Painless aggregation returns the maximum valid ratio per bucket, including dense buckets. Latency differences use paired counters from one observation per bucket, ordered by operation count and then timestamp. These exact queries require inline Painless support on the monitoring store; failures do not fall back to sampling. The previous complete bucket may be read to evaluate the first visible difference; its samples do not rank. Missing or non-adjacent buckets, index UUID/node ID changes, detectable topology changes and counter resets are not scored. Node counter differences assume no JVM restart inside the requested window: a restart resets counters, and the affected transition is skipped by the counter-reset check rather than scored across lifetimes. First-release ranking therefore verifies identity, adjacency, topology and counter monotonicity, but not process lifetime. The Framework keeps the JVM start estimate (`jvm.timestamp - jvm.uptime_in millis` as `start_time_estimate_in_millis`) on the `keep/jvm-start-estimate` branch for a later lifetime check. Storage decreases are skipped but remain the baseline for the next bucket. GC time keeps its legacy per-second formula and units. This is a ranking of retained valid monitoring samples, not proof that collection or counter continuity was perfect.

Queries are limited to 512 visible time buckets, four concurrent exact requests per Console process, up to 32 storage shards per PIT, and a five-second query deadline (or a shorter requested timeout). Composite scans also stop at 48 search pages (including a possible terminal probe) or 150,000 entity-time buckets. The page size is reduced for wider windows. PIT deletion has an independent two-second deadline; short PIT expiry is the fallback if the latest ID is not available. These are protections, not production performance guarantees. Budget or deadline rejection discards any partial ranking and suggests a shorter window, a larger interval, or manual selection. A complete empty result still renders as an empty chart. Agent, unsupported or legacy manual requests, and `doc_percent` retain their existing paths.

## Long-window index summaries

Disabled by default. To enable on-demand summaries on a single Console instance:

```yaml
insight:
  topn:
    summary:
      enabled: true
```

Use `insight.topn.summary` in the configuration. Renaming the setting does not change the summary index or invalidate existing documents.

Setup (`template_ilm`) creates `.console-topn-rollover` and the `.console-topn-index-rate-v2-000001` bootstrap with its write alias on the system monitoring store. The template carries the summary mapping and binds the same ILM/ISM policy as the metrics index; Console only reads and writes that alias and does not create or repair indices or lifecycle bindings. The four supported charts are indexing rate, query rate, indexing latency and query latency. A request with missing summaries queues bounded work for the exact requested window and waits inside the request (up to 30 seconds, or the requested timeout if shorter); a request that arrives while the work runs joins the same job instead of duplicating it. A complete result uses available samples, not an assumed full retention window. A completely evaluated transition can save an empty summary only when both raw dependency buckets are verified. Absent raw buckets never produce summary documents. Only full-index authorization can publish newly computed sealed buckets for metrics on the `metrics` write list. Partial ACL requests and read-only metrics stay in the short process-local cache. Known `raw_gaps` suppress affected transitions rather than rejecting the entire window.

Specify `writer: false` on all but one replica. On-demand requests must reach the writer in multi-instance deployments; other replicas can read existing summaries. Each writer runs at most one on-demand computation at a time; the queue and non-publishable results are process-local and do not survive restart. Hand selection, short windows and other metrics retain their query paths.

Explicit `index`, `read`, `writer`, `clusters`, `metrics` and `read_metrics` settings remain available: `read` and `writer` override their defaults, omitted `metrics` selects all four charts, omitted `read_metrics` follows `metrics`, and omitted `clusters` does not impose a cluster allowlist. The summary target must be a write alias; setup provisions the default. A custom alias requires manual provisioning with the summary mapping and an explicit `index.lifecycle.rollover_alias`, because the shared template binds the default alias. A missing target is computed transiently and not published, so requests still render. Summaries are a cache of the live original source, not a separate historical tier. Both the predecessor and current bucket must match the original backing index names, UUIDs and observation counts in a raw PIT. A missing raw bucket cannot be published; a changed dependency requires a new summary or a bounded raw recomputation. Previously generated summaries without this provenance are not used. Cached background results are also checked before use. The monitoring account needs permission to read the original index UUID settings. This detects retention and changes in observation counts, not same-count in-place edits. Invalidation follows the raw read view. Retention and rollover are owned by setup; replacing the source retention policy requires re-provisioning the summary template and bootstrap, because Console does not rebind them. Summary reads and writes require strict PIT support; stores without it use the bounded raw search.
